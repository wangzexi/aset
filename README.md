# Investment Manager

一个本地运行的 Bun + TypeScript 投资管理器，核心不是基金净值展示，而是把上层持仓尽可能穿透到股票级别。

前端使用 Vite + React + TypeScript，后端使用 Bun。React 会保存每个基金的穿透展开状态，实时行情更新不会重置页面交互状态。

## 当前模型

录入的是每个基金/ETF/股票的当前持有金额。同步时：

1. 基金从东方财富读取最新前十大持仓及报告期。
2. ETF 联接基金先识别底层 ETF，再尝试读取 ETF 的股票持仓。
3. 底层股票行情使用腾讯行情接口，新浪作为备用。
4. 同一只股票来自多个基金时按金额合并，生成组合级股票暴露。
5. 行业字段保留为可扩展维度；当前没有可靠行业数据时显示“未分类”，避免伪造分类。
6. 每日定投在当天首次打开应用时自动入账，同时增加持仓金额和投入成本；重复刷新不会重复入账，周末按交易日顺延。

## 使用

```bash
bun install
bun run start
```

打开 http://localhost:8787/ 。仓库自带一份示例 `data/config.json`（黄金/恒生科技/纳指/沪深300 各四分之一），可直接体验；替换成自己的持仓即可。

## 数据布局

```
data/
├── config.json   # 用户配置：持仓 + 联接基金穿透规则，手工维护
└── cache/         # 穿透日缓存，可随时删除自动重建（gitignored）
```

配置只记录不可推导的最简信息：`code` 是查询主键，`name` 是用户自定义别名，
`shares` 是持有份额。联接基金可加 `underlying.target` 指向跟踪的 ETF，
可选 `sector`/`assetClass` 覆盖展示分类，`fallbackHoldings` 用于无公开持仓
接口的 ETF（如跨境）手工成分兑底。其余一切（市场前缀、权重结构、名称、
行情）均由程序推导。

## 重要限制

基金季度持仓存在披露滞后；ETF 的穿透依赖公开持仓接口；最终估值和暴露仅供参考。累计收益暂未纳入交易流水，当前页面重点是持仓金额、股票级穿透和今日估算。
